# Credit Flow — архитектурные документы

Все документы имеют статус **Draft v1**; отдельные документы обновлены до версии 1.1 после согласования модели восстановления заявки. Комплект нужно согласовать целиком до реализации.

- `requirements.md` — бизнес-цели, функциональные и нефункциональные требования.
- `service-boundaries.md` — ответственность сервисов, владение данными и взаимодействия.
- `application-lifecycle.md` — состояния заявки, переходы, processing hold и восстановление процесса.
- `event-catalog.md` — Kafka-события, команды resume, Outbox/Inbox, retries и эволюция схем.
- `security-model.md` — границы доверия, роли, аутентификация и защита данных.

Согласованное решение по восстановлению: технические повторы и повторное бизнес-рассмотрение разделены; processing hold не является публичным статусом; ручной resume авторизуется и аудируется; resume не разрешён для терминальных статусов; повторное рассмотрение после `REJECTED` исключено из MVP.

Изменения, затрагивающие архитектурные решения, фиксируются в ADR; изменившиеся требования отражаются в документах и тестах.
